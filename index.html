它解决什么问题

每拿到一份新数据，都要重复做描述统计、画图、试模型、写结论；而非技术同事又看不懂代码输出。 这个 Agent 把这条链路自动化，并且把「重计算」全部留在本地：数值统计、特征工程、模型训练都在本机完成， 大模型只负责决策与撰写结论 —— 因此结果可复现、数值可信、调用成本低。

工作流程

① 画像与质量诊断：自动识别列语义（数值/类别/时间/文本/ID），输出统计摘要、缺失率、离群值、 共线性（VIF）、疑似泄漏字段，并给出 0~100 的数据质量评分与处理建议。
② 分析方向建议：按数据维度说明该看什么、适合哪类方法（线性 / 非线性 / 树模型 / 集成 / 神经网络）、 适用前提与注意事项，并列出可选作标签的候选列。
③ 建模与解释：基线 → 线性 → 多项式 → 随机森林 → 梯度提升 → 神经网络，统一交叉验证评估； 附特征重要性、部分依赖曲线（PDP）、残差诊断与混淆矩阵。
④ 结论与报告：Agent 调用大模型撰写中文结论，一键产出 HTML（自包含图表）/ Excel（多表单）/ Markdown 三种报告。

技术实现

1. Agent 核心（Function Calling 多轮循环）

  • 把分析能力封装为 16 个工具（画像 / 分组汇总 / 假设检验 / 相关分析 / 可视化 / 特征工程 / 训练模型 / 模型解释 / 预测 / 聚类 / 联网检索 / 出报告），每个工具带 JSON Schema 描述，交给模型自主调度。
  • 实现多轮「思考 → 调用工具 → 回填结果 → 继续思考」循环，工具执行结果实时流式回显给用户（Flask + SSE）。
  • 意图识别 + 工具子集动态路由：按用户问题只发送 6~12 个相关工具（问"有哪些维度"只发分析类， 问"预测流失"才带建模类），工具定义开销从 2757 降至 631~1109 tokens/轮。

2. Token 成本优化（本项目重点）

工具 Schema 精简压缩参数描述与枚举，去掉冗余字段2757 → 1615 tokens
按意图筛选工具关键词意图匹配 → 只发相关工具组降至 631~1109 tokens/轮
前缀缓存友好易变的数据上下文拆为独立消息，保证 system + tools 前缀字节稳定缓存命中 44%~57%，该部分按约 1/10 计价

轮次与预算闸门三档成本模式 + 单会话 token 预算上限 + 同工具单轮调用上限成本可预期、可硬约束

3. 数据分析能力层

  • 可视化 15 类：分布 / 箱线 / 类别 / 时间趋势 / 散点 / 相关热力图 / 缺失 / 散点矩阵 / 特征重要性 / 部分依赖 / 残差 …， 每张图同时产出 Plotly 交互版与 Matplotlib 报表版。
  • 统计检验 8 类：Pearson/Spearman/Kendall 相关、Welch t 检验、单因素 ANOVA、卡方独立性检验， 并输出效应量（Cohen's d、Cramér's V、η²）与 VIF 共线性诊断。
  • 特征工程 16 类算子：中位数/众数填充、缺失指示变量、对数变换、分位数缩尾、比值、交互项、等频分箱、 时间特征（年/月/星期/周末/月度 sin-cos）、频率编码、目标编码、文本特征、分组统计特征。
  • 模型 11 类：基线、线性/Logistic、Ridge、Lasso、多项式（非线性）、决策树、随机森林、 HistGradientBoosting、KNN、SVM、MLP 神经网络；统一预处理管线与交叉验证，保证横向可比。
  • 无监督：标准化 → PCA 降维 → KMeans/层次/DBSCAN 聚类，按轮廓系数自动选簇数，输出簇画像热力图与业务命名建议。

4. 工程实现

  • Flask 后端 + Server-Sent Events 流式通道，工具执行过程逐条推送到前端；前端为零依赖单文件 HTML/JS，无需构建。
  • 无 API Key 降级：未配置密钥时自动切换规则引擎，画像、统计、建模、聚类与报告全部照常，功能不中断。
  • 模块化拆分为 12 个 Python 模块（数据引擎 / 可视化 / 建模 / 工具层 / Agent / 报表 / 搜索 …）， 配 3 个端到端自测脚本与中文文档。

5. 攻克的工程问题

  • 并行受限导致树模型崩溃：受限环境下 joblib 创建线程池失败（WinError 5），随机森林/GBDT 直接报错。 增加运行时能力探测，探测到不可用即自动降级单线程，功能不受影响。
  • SDK 版本不兼容引发的静默降级：openai 3.x 与 httpx 0.28 冲突导致所有 API 调用抛 TypeError，而异常被吞掉后系统"看似正常"实则全程未调用模型。改为原生 HTTP 客户端实现协议， 并把真实错误暴露到界面与日志。
  • 类型序列化陷阱：JSON 转换层漏了 Python 原生 int 分支，导致统计值变成字符串、 下游比较报错；补齐类型分支并加回归自测。
  • 性能优化：图表抽样 + 树数量按样本量自适应，全流程耗时 33s → 16s。
